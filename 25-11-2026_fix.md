# Production Readiness Audit & Locked Specification — 2026-11-25

Full-codebase multi-specialist audit and locked implementation specification for `priqi_iced` (`iced 0.15.0-dev` @ `cd04b74ca7073766f654535d6e72c452ef749d07`, `sqlx 0.9` SQLite, `labelize 1.9`).
No `src/` files have been modified; this document serves as the authoritative production remediation contract.

## 0. Locked Design & Architecture Decisions (`/grill-me` Specification)

1. **Database Source of Truth ([src/core/db/mod.rs](src/core/db/mod.rs)):**
   - The project's local `priqi.db` schema (`templates` and `datasets` tables in `src/core/db/mod.rs`) is the **sole source of truth** (any external databases in `%APPDATA%` are unrelated and ignored).
   - Harden `Db::init()` with SQLite `WAL` journal mode, `busy_timeout(5s)`, `synchronous(NORMAL)`, `Db::delete_dataset`, and per-template `width_mm`, `height_mm`, and `dpi` columns (with idempotent migration for existing `priqi.db` files).
2. **Printer Discovery & Spooling ([src/core/printer.rs](src/core/printer.rs), [src/core/controls/](src/core/controls/)):**
   - Replace hardcoded dummy printers (`"Térmica 80mm"`, `"Laser Escritório"`) by enumerating real installed Windows print queues via the Win32 Print Spooler (`winspool.drv` `EnumPrintersW`) alongside `"Salvar em PDF"`.
   - When an OS printer is selected, send RAW ZPL byte streams directly to the selected Windows printer queue (`OpenPrinterW` -> `StartDocPrinterW` with `"RAW"` datatype -> `StartPagePrinter` -> `WritePrinter` -> `EndPagePrinter` -> `EndDocPrinter` -> `ClosePrinter`) inside an async background task (`Task::perform` / `spawn_blocking`).
3. **PDF Export (`"Salvar em PDF"` in [src/core/printer.rs](src/core/printer.rs)):**
   - Open a native Windows Save File dialog (`comdlg32.dll` `GetSaveFileNameW` with `.pdf` filter) and generate a single multi-page `.pdf` file containing one page per rendered label × `copies` (across all `^XA...^XZ` blocks in the ZPL document).
4. **CSV Import & Ragged Row Normalization ([src/core/datasets/update.rs](src/core/datasets/update.rs), [src/core/widgets/import_modal/](src/core/widgets/import_modal/)):**
   - **Paste Import:** Importing via the `"Colar conteúdo"` (`Paste`) tab **always creates a new dataset** (`"Dataset Importado N"`), matching file import behavior so existing datasets are never silently overwritten.
   - **Ragged / Wide Rows:** When an imported CSV has rows with more fields than the header row (`row.len() > headers.len()`), auto-extend `headers` with generated `"COLUNA N"` names to match the widest row and pad shorter rows to uniform width so no data is lost and SQLite CSV serialization never fails.
   - **Delimiter Auto-Detection:** Auto-detect `,` vs `;` (and `\t`) from the header line so semicolon-delimited CSVs highlighted by `CsvParser` parse into proper columns.
5. **Empty Dataset Row Selection Rule (`selected_rows.is_empty()`):**
   - When a dataset has rows but 0 rows are selected (`"Limpar seleção"`), show the raw unsubstituted template in **both** the main `Preview` tab and the sidebar template thumbnails, and **disable printing** (or return a clear validation error `"Selecione ao menos uma linha para imprimir"`).
6. **Dataset CRUD via Inline Action Buttons (No Separate Popups) ([src/core/datasets/](src/core/datasets/)):**
   - Improve the existing Datasets panel directly with inline action buttons (no confirmation modal popups):
     - **Rename Active Dataset:** Inline rename icon button next to the dataset dropdown that swaps in an auto-focused `text_input` (matching template rename UX).
     - **Delete Active Dataset:** Inline delete icon button (`trash`) next to the dataset dropdown that deletes the active dataset from memory and SQLite (`Db::delete_dataset`) and selects the next available dataset.
     - **Delete Selected Row(s):** Inline action button in the table selection bar (`"Excluir selecionadas"`) that removes all indices in `selected_rows` from the active table.
     - **Delete Column:** Inline delete button (`x` / `trash`) inside each column header cell that removes that column from `headers` and every row.
7. **Label Size (`W × H` mm) & DPI Controls ([src/core/editor/preview/](src/core/editor/preview/), [src/core/renderer.rs](src/core/renderer.rs)):**
   - Add compact label dimensions (`width_mm × height_mm`) and DPI (`203` / `300` / `600` DPI) controls in the Preview toolbar, persist them per template in SQLite, and pass them to `labelize::DrawerOptions`.
8. **Bottom Print Controls Drawer & Copies Slider ([src/core/controls/](src/core/controls/), [src/core/view.rs](src/core/view.rs)):**
   - Keep the collapsible bottom-center drawer design.
   - Remove the 10px bottom gap when collapsed and fix the 3px double-border seam between `toggle_button` and `card`.
   - Add bottom padding/inset to the Editor/Preview when the drawer is expanded so bottom content is not occluded.
   - Fix vertical alignment between the printer dropdown and copies slider, keeping the copies slider clean **without** `+/-` stepper buttons.

## 1. Bugs (Data Loss, Broken Logic & Rendering Defects)

### 1.1 [P0] Imported CSV datasets with ragged/extra columns silently fail to persist to SQLite (Permanent Data Loss)
- **Locations:** [src/core/datasets/update.rs:254-273](src/core/datasets/update.rs#L254-L273), [src/core/db/mod.rs:132](src/core/db/mod.rs#L132), [src/core/db/mod.rs:156-193](src/core/db/mod.rs#L156-L193), [src/core/update.rs:405-417](src/core/update.rs#L405-L417), [src/core/datasets/widgets/dataset_table.rs:81-87](src/core/datasets/widgets/dataset_table.rs#L81-L87), [src/core/datasets/widgets/dataset_table.rs:238](src/core/datasets/widgets/dataset_table.rs#L238)
- **What happens:**
  1. `parse_csv_to_table` sets `.flexible(true)` ([src/core/datasets/update.rs:257](src/core/datasets/update.rs#L257)) and pads rows shorter than `headers.len()` ([lines 266-268](src/core/datasets/update.rs#L266-L268)), but keeps rows wider than `headers.len()` untouched.
  2. When `spawn_save_dataset` calls `db.save_dataset`, `table_to_csv_strings` ([src/core/db/mod.rs:161-164](src/core/db/mod.rs#L161-L164)) constructs `csv::WriterBuilder::new().from_writer(vec![])` with the default `flexible(false)`. Calling `w_rows.write_record(row)?` on rows of unequal length deterministically fails with `csv::ErrorKind::UnequalLengths`.
  3. Because `spawn_save_dataset` ([src/core/update.rs:413](src/core/update.rs#L413)) discards the result with `let _ = db.save_dataset(...).await;`, the dataset works in memory during the session and **vanishes completely on app restart**.
  4. In the UI, `dataset_table.rs` fixes `total_width` to `table.headers.len()` ([lines 84-87](src/core/datasets/widgets/dataset_table.rs#L84-L87)) while `row_data.iter().enumerate()` ([line 238](src/core/datasets/widgets/dataset_table.rs#L238)) renders every extra cell without `.take(col_count)`, overflowing the fixed-width row container.
- **Locked Fix:** In `parse_csv_to_table`, find the maximum row length across headers and all records, auto-extend `headers` with unique `"COLUNA N"` names up to `max_cols`, and pad all rows to `max_cols`.

### 1.2 [P0] Counter-based ID generation causes primary key collisions, overwriting templates/datasets in SQLite and duplicating cards in memory
- **Locations:** [src/core/update.rs:56](src/core/update.rs#L56), [src/core/update.rs:70](src/core/update.rs#L70), [src/core/templates/update.rs:11-21](src/core/templates/update.rs#L11-L21), [src/core/templates/update.rs:41-50](src/core/templates/update.rs#L41-L50), [src/core/datasets/update.rs:25-29](src/core/datasets/update.rs#L25-L29), [src/core/datasets/update.rs:178-193](src/core/datasets/update.rs#L178-L193), [src/core/db/mod.rs:80-85](src/core/db/mod.rs#L80-L85), [src/core/db/mod.rs:136-143](src/core/db/mod.rs#L136-L143)
- **What happens:**
  - `template_counter` and `dataset_counter` are initialized from `.len()` on startup ([src/core/update.rs:56, 70](src/core/update.rs#L56)).
  - If `template_1` through `template_5` exist and `template_1` is deleted (either in the current session or before a restart), `.len()` becomes `4`. Adding a template increments `template_counter` to `5` and generates `"template_5"`.
  - In memory, `state.templates.push(new_template)` creates duplicate entries sharing `id == "template_5"` (both cards highlight simultaneously, and deleting one via `retain(|t| t.id != id)` deletes both).
  - In SQLite, `INSERT ... ON CONFLICT(id) DO UPDATE` silently overwrites the existing `template_5` with blank default ZPL.
  - The same collision affects `dataset_counter` in `state.datasets.tables` and SQLite `datasets`.
- **Locked Fix:** Initialize `template_counter` and `dataset_counter` from the maximum existing numeric suffix (and advance monotonically while checking `!exists`) so generated IDs never collide with existing records.

### 1.3 [P0] Duplicate `"COLUNA 1"` / `"COLUNA 2"` headers created by `AddColumn` break ZPL `[COLUNA N]` substitution
- **Locations:** [src/core/datasets/models.rs:89](src/core/datasets/models.rs#L89), [src/core/datasets/update.rs:30-33](src/core/datasets/update.rs#L30-L33), [src/core/datasets/update.rs:124-130](src/core/datasets/update.rs#L124-L130), [src/core/update.rs:60-71](src/core/update.rs#L60-L71)
- **What happens:** `state.datasets.column_counter` starts at `0` and is never updated when `AddDataset` creates initial headers `["COLUNA 1", "COLUNA 2"]` ([src/core/datasets/update.rs:31](src/core/datasets/update.rs#L31)), nor when datasets are loaded from SQLite or imported from CSV. Clicking `+` (`AddColumn`) increments `column_counter` to `1` and `2`, appending duplicate `"COLUNA 1"` and `"COLUNA 2"` columns.
- **Locked Fix:** Compute the next column name per table by finding the smallest `N >= 1` where `!table.headers.iter().any(|h| h.eq_ignore_ascii_case(&format!("COLUNA {N}")))`.

### 1.13 [P1] Unclosed `[` in `ZplParser` disables syntax highlighting for the remainder of the line, and 3-letter ZPL commands are mis-tokenized
- **Locations:** [src/core/editor/code/widgets/highlighter.rs:8-12](src/core/editor/code/widgets/highlighter.rs#L8-L12), [src/core/editor/code/widgets/highlighter.rs:47-73](src/core/editor/code/widgets/highlighter.rs#L47-L73)
- **What happens:**
  - When `bytes[i] == b'['` ([line 64](src/core/editor/code/widgets/highlighter.rs#L64)), the scanner advances `i` until `b']'` or `len`. If no closing `']'` exists on that line (e.g., while typing `[COL` or a literal `[` in `^FD`), `i` stays at `len` instead of backtracking to `start + 1`, suppressing syntax highlighting for all tokens after it on the same line.
  - Bare `^` or `~` emits a 1-byte `ZplToken::Function`; `^A0N` leaves `N` unhighlighted; 3-letter ZPL commands (`^CFE`, `^FWR`, `^JMA`, `^JUS`, `^MMT`, `^PON`) are truncated to 2 letters; `^FX` comments are not handled.
- **Locked Fix:** Backtrack `i = start + 1` when no matching `']'` is found before `[` or EOL, require at least one valid mnemonic character after `^`/`~`, and support `^FX` comments and 1–3 letter ZPL mnemonics.
